# Incident: 2026-04-07 08:00:00

## Summary

Starting around 08:00 UTC on April 7, 2026, every pizza order placed through JWT Pizza failed with a 502 error. The upstream Pizza Factory was returning HTTP 500s with the message "chaos monkey" on all order requests. This lasted roughly 8 hours until it was resolved at ~16:00 UTC. Every user who tried to order during that window got an error - 100% failure rate on pizza creation. The failure was caught by a Grafana error-rate alert that fired at 15:55 UTC.

## Detection

The "High HTTP Request" alert fired in Grafana at approximately 15:55 UTC, showing a spike in error-level log entries from `jwt-pizza-service`. I received an email notifying me of the alert, and double checked in grafana, where I saw the same error while checking Grafana Alert Activity.

The big problem: There was however an issue with the push notifications. The email ended up going to my spam folder because of the restrictions I have on my BYU email. Because of that, I lost a lot of time which ended up costing about 8 hours of undetected downtime. If I'd had a "Pizza Creation Failures" alert configured from the start (fires within minutes of the first failed order), I would have caught this much earlier. Cutting detection time in half just requires wiring up a phone notification.

## Impact

For roughly 8 hours between 08:00 UTC and 16:00 UTC on April 7, 2026, pizza ordering was completely broken. Every order attempt returned: `{"message": "Failed to fulfill order at factory", "upstreamMessage": "chaos monkey"}`. All users who tried to order pizza during this window were affected. No support tickets were filed since this is a dev/test environment.

All times are UTC.

## Response

I noticed the firing alert at ~15:57 UTC while checking Grafana. Luckily, while there was no push notification from the received email (that was sent to my spam), I just happened to look in the spam folder and noticed the email. I then went to my grafana dashboard. I placed a test order via the admin account to reproduce the failure, which returned a `followLinkToEndChaos` URL in the response body. Opening that URL in the browser immediately resolved the chaos. Total time from detection to resolution was about 3 minutes once I was actually aware of the problem.

The delay wasn't in the fix, it was in finding out there was a problem in the first place. 8 hours passed before I saw it.

## Root cause

The Pizza Factory injected chaos that made it return HTTP 500 ("chaos monkey") for every order fulfillment request. `jwt-pizza-service` correctly passed the failure back to the client and logged the factory's `reportUrl`, but there were no alerts in place that would have paged me immediately when orders started failing.

## Resolution

I visited the URL returned in the `followLinkToEndChaos` field of the failed order response: `https://pizza-factory.cs329.click/api/support/87879e07c1464295bad4eb5a0dd7f380/report/66guxtnf`. Opening it told the factory to end the chaos, and orders started succeeding again immediately. No code changes were needed.

Going forward, the `reportUrl` shows up in the service logs on every failed order. A Grafana log alert querying for `reportUrl` in logs would surface both the problem and the fix link at the same time, cutting resolution time significantly.

## Prevention

This is the first chaos incident on this system so there is no prior history to compare against. The root issue, undetected upstream failures, could affect any external dependency, not just the Pizza Factory. The fix is making sure alerts are loud enough to actually page someone, not just appear in a dashboard nobody is watching.

## Action items

2. Keep the new "Pizza Creation Failures" alert rule active, evaluated every 1 minute
3. Keep the new "High HTTP Request" error-rate alert active as a general-purpose catch-all

## Changes made

The following alert rules were created in Grafana during/after this incident, none of them existed when chaos started:

- **Pizza Creation Failures**, fires when `sum(sum_over_time({source=~"jwt-pizza-service(-dev)?", metric="pizza"} | json | __error__="" | unwrap failures [5m])) > 0`
- **Auth Failures spike**, fires on elevated authentication failure rate
- **High HTTP Request**, fires when `count_over_time({source=~"jwt-pizza-service.*"} | json | level="error" [5m]) > 0`

These were not in place when the chaos started, which is why detection took ~8 hours instead of minutes.
